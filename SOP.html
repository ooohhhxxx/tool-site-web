标准操作程序（SOP）

一、目的

为规范「调试工具」（以下简称"本工具"）的安装、配置与日常使用，确保操作人员能够正确、安全地完成 SSH 远程管理、Modbus TCP 通信调试、西门子 S7 PLC 调试与串口设备调试，降低误操作风险，提高排障效率，特制定本 SOP。

二、适用范围

  • 需要同时管理 SSH 主机、Modbus TCP 设备、西门子 S7 PLC 与串口设备的现场调试、运维、产线排障场景；
  • Windows 10 / 11 x64 桌面环境；
  • 本工具与「经典 Tk 版调试工具」是两个独立软件，可同时安装、互不影响。本 SOP 只适用于桌面版 v1.0.7。

四、安装、升级与卸载

4.1 首次安装

  1. 从官网下载 UltimateToolWeb-Setup.exe，建议核对版本清单 version.json 中的 SHA256。
  2. 双击安装包，按向导完成；可勾选「创建桌面快捷方式」。
  3. 默认安装到 C:\Program Files (x86)\UltimateToolWeb（或 Programs 目录），AppId 与经典 Tk 版不同，不会覆盖旧软件。
  4. 安装完成可直接勾选「立即启动」。

4.2 升级（推荐：在线更新）

  1. 打开「设置」页，软件更新区在启动时会按设置自动检查一次线上版本清单；也可随时点「检查更新」手动触发。
  2. 发现新版本后显示版本号、包大小与更新说明，点「下载更新」。程序按国内镜像优先的顺序尝试多个下载源，某个源失败会自动换下一个，界面显示进度百分比。
  3. 下载完成后自动做 SHA256 校验，校验不通过会丢弃文件并报错，不会安装坏包；通过后按钮变为「立即安装」。
  4. 点「立即安装」会启动安装向导，并自动关闭本程序（覆盖安装要求旧进程先退出）。按向导完成即可。
  5. 也可手动到官网下载新安装包，运行后安装到相同目录覆盖升级，无需先卸载（AppId 未变）。
💡 用户数据（连接记录与已加密的密码、窗口几何、插件开关）都存放在用户目录，覆盖安装不会清除。在线更新只使用 127.0.0.1 之外的官网/Gitee 地址，不会上传任何本机配置。

4.3 卸载

通过「设置 → 应用 → 安装的应用」或开始菜单的「卸载」入口执行。卸载不会删除用户目录下的配置与日志文件，需要彻底清理时手动删除第十一节列出的路径。

⚠️ 本软件未购买数字签名证书，Windows Defender / 360 等可能误报，请先核对 SHA256 再添加信任。

五、启动、单实例与运行原理

  1. 双击桌面图标或开始菜单「调试工具」。
  2. 启动器先补好无控制台环境下的标准输出流，随机选一个本机空闲端口，后台线程启动 uvicorn。
  3. 主线程创建 WebView2 原生窗口（标题「调试工具」），加载本机前端页面。
  4. 关闭窗口 → 停服务 → 清理单实例登记 → 进程退出（实测退出码 0）。

5.1 单实例

程序用 Windows 命名互斥体保证只跑一个主实例。再次双击图标时不会新开进程，而是把已有窗口还原、前置后退出；若已有窗口被最小化，会被恢复显示。这样可避免两个进程共用 WebView2 配置目录、互相覆盖连接记录，以及争抢同一个串口 COM 口。

💡 确实需要两个窗口并排时，可用命令行设置环境变量 UTWEB_NEW_INSTANCE=1 再启动。该实例会使用独立的 WebView2 配置目录，连接记录不与主实例共享。

六、SSH 远程管理操作流程

  1. 左侧点「SSH 远程管理」，右上「新建主机」，填写主机、端口、用户名、密码（或私钥）与编码，确认连接。
  2. 连接成功后新增一个会话标签；多个主机可同时保持多个标签，点标签切换，标签上的 × 关闭单个会话。
  3. 中间深色区域是 xterm 终端，直接键入命令；支持选中复制、Ctrl+滚轮或设置页缩放字号、清屏。
  4. 右侧「远程文件」面板可列目录、过滤、上下载、新建目录、删除、返回上级；路径栏可直接输入跳转。右键文件可「查看 / 编辑」（直接读写远端文本文件，超过 2 MB 会提示下载后本地编辑；保存时先写临时文件再替换，断线不会截断原文件）、重命名、修改权限（八进制，如 644 / 755）、删除与刷新目录。
  5. 终端与文件面板之间的竖直分割条可拖动改宽度，双击恢复默认 62%；窗口过窄时自动改为上下堆叠。
💡 部分交换机 / 工控机没有安装 sftp-server，此时 SFTP 会建立失败，程序会自动降级为纯终端，终端仍然可用，文件面板显示「未连接或 SFTP 不可用」属正常现象。
💡 连接记录已保存密码：新建主机时填一次密码即可，左侧选中记录后点「连接选中记录（免密）」或双击记录直接连接，不用每次重输。密码用 Windows DPAPI 加密存在本机用户目录，前端列表接口不回显任何凭据。右键记录可打开「连接 / 编辑记录 / 删除记录」菜单；编辑时可改主机、端口、用户名、密码、编码与备注，密码留空表示沿用已保存的密码。未保存密码的记录会提示先编辑补上。
⚠️ 在终端执行 rm、reboot、shutdown 等破坏性命令前，务必反复确认目标主机与路径，防止误操作生产环境。

七、Modbus TCP 调试操作流程

  1. 左侧点「Modbus TCP」，填写设备 IP、端口（默认 502）、超时后点「连接」。
  2. 「快速读写」区选择功能码与地址，执行单次读 / 写；写入前请确认地址含义。
  3. 添加监控点位后可批量轮询，当前值与变化在表格中显示；双击「备注」列可改名（默认是「点位 N」，现场点位多时建议按用途命名）；报文日志记录每帧交互，便于对线。
  4. 左右分栏之间有可拖动分割条，双击恢复默认 58%。
🚨 安全红线：对运行中的设备（尤其是控制物理动作的 PLC）写入任何线圈或寄存器前，必须与现场人员确认地址含义。擅自写入可能导致设备动作或生产事故！

八、S7 PLC 调试操作流程

  1. 左侧点「S7 PLC」，填写 PLC 的 IP、端口（默认 102）、机架与槽位（S7-1200/1500 常用 0/1，S7-300 常用 0/2）、超时，点「连接」。连接成功后状态栏会显示 PDU 协商结果。
  2. 「快速读写」区输入地址：DB1.DBX0.0（位）、DB1.DBB0（字节）、DB1.DBW0（字）、DB1.DBD0（双字），位存储区写 M10.0，输入/输出写 I0.0 / Q0.1。类型可选「自动」按地址后缀推断，也可显式指定 BOOL / BYTE / WORD / INT / DWORD / DINT / REAL。
  3. 读取时填「数量」可一次读多个元素（BOOL 读多个位会显示成 0/1 序列）。写入值支持逗号分隔的多个值（如 1,0,1,1 写 4 个位、1,2,3 写 3 个字），BOOL 按位打包。写整型地址时传小数会被明确拒绝，需写浮点请把类型选成 REAL。
  4. 地址表：把常用地址加入监控列表并给备注，点「开始轮询」按设定间隔刷新。所有点位会合并成一次请求（每批最多 20 个地址），状态栏显示本轮耗时与请求次数；某个地址读失败只把该行标红并显示原因，不影响其他点位。地址表保存在本机，刷新页面不丢。
  5. 块读取 / 结构解析：填起始地址与字节长度，点「读取块」一次读回整块，再按「偏移 + 类型 + 数量」在右侧表格拆成多个字段——BOOL 按位偏移，其他类型按字节偏移；可切换十进制 / HEX / 位图显示，并查看原始报文。适合一次解析一个结构体，比逐字段请求少很多往返。
  6. 左右分栏之间有可拖动分割条，双击恢复默认。
🚨 安全红线：向运行中的 PLC 写入 DB / M / Q 区域前，必须与现场人员确认地址含义与允许范围。误写可能直接触发设备动作或造成生产事故！
💡 连不上或读不到数据的三个常见原因：① S7-1200/1500 未在 CPU 属性中勾选「允许来自远程对象的 PUT/GET 通信访问」；② 数据块勾了「优化的块访问」，必须取消后才能用 DB1.DBX 这类绝对地址读写；③ 机架/槽位填错（1200/1500 多为 0/1，300 多为 0/2）。另外端口 102 需网络可达，现场交换机或防火墙可能拦截。

九、串口调试操作流程

  1. 左侧点「串口调试」，点「刷新端口」枚举本机 COM 口，选择端口、波特率、数据位、校验位、停止位与编码，点「打开串口」。
  2. 在发送区输入内容，可选 HEX 模式（字节用空格分隔）、自动换行、定时循环发送；Ctrl+回车 直接发送。
  3. 接收区实时显示，可切换 HEX / 文本视图、暂停、自动滚动、清空；底部显示 TX / RX 字节计数。
  4. 左右分栏之间同样有可拖动分割条，双击恢复默认 50%。
⚠️ Windows 的串口是独占资源。若提示「端口被占用」，请关闭其他串口助手、PLC 编程软件，或确认没有第二个本工具实例在跑（见 5.1）。循环发送间隔建议不小于 50ms。

十、插件功能

  1. 左侧点「插件」，页面列出已发现的插件、版本、状态与说明。
  2. 用开关启用 / 停用插件；选中插件后双击命令即可执行，长任务可点「停止」。
  3. 执行日志通过 WebSocket 实时推送到页面下方。
  4. 用户插件目录 ~/.ssh_gui_plugins 优先级高于内置目录，同名插件可覆盖。
💡 内置 3 个示例插件共 9 个动作：SSH 批处理、Modbus 扫描、串口 HEX。插件沿用经典 Tk 版的 PluginBase 契约，已有插件可直接复用。

十三、安全与合规

  • 程序不访问外网、不上传任何连接信息或设备数据，全部通信由操作人员主动发起；
  • 对生产设备执行写操作（Modbus 写入、SSH 破坏性命令、串口控制指令）前必须双人确认；
  • 删除远程文件不可恢复，删除前逐字核对完整路径；
  • 本软件为个人免费工具，无数字签名，请从官方仓库核对 SHA256 后再分发。

13.1 本地服务边界（务必知悉）

⚠️ 程序在本机 127.0.0.1 上起一个 HTTP 服务供界面调用，该服务没有账号密码。它已做三重来源校验（Origin 与 Host 同源、浏览器请求要求 Host 为本机、拒绝跨站请求；WebSocket 同样校验），可以挡住「别的网页偷偷调用本工具」。但同机器上的其它程序仍可直接调用这些接口（SSH 终端、PLC 读写、串口发送、插件执行）。因此：
  • 不要在与他人共用的机器、或在多人登录的远程桌面会话中长期开着本工具；
  • 离开座位前断开设备连接或关闭程序（关闭后服务随之退出）；
  • 不要把本机随机端口通过内网穿透、反向代理等方式暴露到其它机器。

13.2 插件与配置文件

  • 插件是本地 Python 代码，运行在程序进程内、拥有全部能力（可读写任意文件、发起网络连接、操作已连接的设备）。只加载自己确认过来源的插件，不要从不明渠道下载 .py 插件放进插件目录。
  • 配置备份（含连接记录）导出时不包含密码；导入时只接受程序已知的设置项，手改备份文件里的未知字段会被忽略。
  • 连接密码用 Windows DPAPI 加密后存在当前用户目录，换用户或换机器后需重新输入。

13.3 在线更新

  • 更新清单与安装包都通过 HTTPS 从官方 Gitee / GitHub 仓库获取，下载完成后强制比对 SHA256，安装前再校验一次，不匹配即拒绝执行。
  • 由于程序未购买代码签名证书，SHA256 只能证明「下载到的文件与清单里写的一致」；若官方仓库本身被入侵，理论上可下发被替换的安装包。请在下载页核对版本号与文件大小，发现异常先不要安装。

十四、已知限制

  • 依赖系统 WebView2 Runtime；老机器可能需要单独安装 Evergreen Bootstrapper。
  • 在线更新已内置；托盘最小化、全局快捷键、文件关联与命令行传参暂未实现。
  • 设置页部分开关为原型占位（见第十一节）。
  • 在线更新依赖能访问官网或 Gitee；完全离线的环境请手动下载安装包覆盖升级。
  • S7 模块为纯 Python 协议栈，已用内置模拟服务端做字节级校验，但真机兼容性（批量读的 PDU 预算、位数组、写数据项编码）仍需现场验证。
  • S7 暂不支持符号寻址、程序块上传/下载与 PLC 启停；S7CommPlus（S7-1200 V4+ 的加密协议）不在支持范围内。
  • 未做 WebView2 Runtime 的随包分发，离线纯净系统需提前准备运行时。

十五、场景编排与诊断知识库

场景编排用于把一次排障动作固化成可重复执行的流程；诊断知识库用于把「现象 → 原因 → 处置」沉淀下来。两者配合，现场排障从「凭经验挨个查」变成「跑一遍、看结论」。

15.1 前置条件

  • 先在对应的协议页（SSH / Modbus / S7 PLC / 串口 / HTTP 调试）把设备连上，确认单独操作正常；
  • 场景步骤只调用已经连好的连接，不会自己发起连接，也不会保存账号密码——凭据仍留在各协议页的连接记录里；
  • 场景页顶部会提示「未连接：Modbus / 串口…」，用到这些协议的步骤会直接失败，不是工具故障。

15.2 新建与编辑场景

  1. 进入「场景编排」，填写「名称」（如"网关健康检查"）与「说明」；
  2. 在右上角选择步骤类型后点「添加步骤」。可选：SSH 执行命令、Modbus 读/写寄存器、S7 读/写变量、串口收发、HTTP GET、HTTP 请求、等待；
  3. 点开步骤填参数：Modbus 需选寄存器区并填地址（0 基）、S7 填 DB1.DBD0 这类绝对地址、HTTP 填完整 URL、串口可切换十六进制发送；
  4. 需要判定结果时设「断言」：等于 / 不等于 / 大于 / 小于 / ≥ / ≤ / 在区间内 / 包含 / 不包含 / 正则匹配 / 非空 / 为空。断言对象是这一步的"主要取值"：SSH 取输出、寄存器取数值、串口与 HTTP 取回包文本；
  5. 需要在后面复用时填「存为变量」（如 ver），后续参数里写 ${ver} 即可引用，支持 ${a.b.0} 形式取嵌套值；
  6. 可选设置：重试次数（0–3）、单步超时（0.5–120 秒）、失败是否继续。默认是"失败即停"，避免后续步骤在下游状态不确定时继续写设备；
  7. 点「保存」写入本机；场景文件在用户目录 .ultimatetool_web_scenarios，可直接复制给同事。

15.3 运行与结果

  • 点「运行」后逐步执行，右侧实时显示每步结果、耗时、取到的值与错误；
  • 结果分四种：通过（含断言通过）、断言失败（执行成功但值不符）、出错（连接/协议异常）、跳过（步骤被禁用）；
  • 写操作仍受「只读模式」拦截、仍写入审计日志——编排不能绕过保护；
  • 「停止」会在当前步骤结束时立即停下（等待类步骤会立刻中断）；
  • 点「导出报告」生成 Markdown，含逐步结果表与可能原因，可直接贴到工单或群里。运行历史保留最近 200 次。

15.4 诊断知识库

  • 内置 13 条条目，覆盖本项目现场真踩过的问题：SFTP 子系统缺失、paramiko 4 移除 SHA-1 算法、RTU 超时、Modbus 02/03 异常码、CRC 干扰、COM 口被占用、S7 rack/slot 与优化块、串口无回包、HTTP 4xx 等；
  • 场景某步失败时，结果下方会自动列出最可能的原因与处置（最多 3 条）；
  • 支持按现象/关键词搜索与按协议过滤；
  • 可新建、编辑、删除自己的条目；内置条目不可修改也不可删除（避免工具升级后覆盖），点「编辑」会自动转为"另存为我的版本"。

15.5 边界

  • 只支持线性步骤，没有循环与条件分支；批量设备巡检需复制多份场景；
  • HTTP 步骤为 GET，接口需要鉴权时可在参数里补 headers；
  • 串口步骤是"发一条、等回包"，回包静默 50ms 即认为结束，不做长连接监听；
  • 场景运行期间修改步骤不影响本次运行（运行使用启动时的快照）。
